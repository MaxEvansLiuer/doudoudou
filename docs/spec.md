## 一、样例逆向分析（这是需求的真正来源）

| # | 来源/标题 | 尺寸 | 色数 | 总豆数 | 粗线间隔 | 图例 | 水印 |
|---|---|---|---|---|---|---|---|
| 1 & 5 | `小猪佩奇边角料-土豆先生_镜像 … [34x49/7色/共756颗]` | 34×49 | 7 | 756 | 5 格 | 底部，**被裁掉一半** | 有（浅色App水印） |
| 2 | `土豆先生 ©小槿 [33x40/7色/共283颗]` | 33×40 | 7 | 283 | 10 格 | 底部完整，带数量 | 有 |
| 3 | `Mard-221 ·（50x50尺寸·8色）` + `共899豆子` | 50×50 | 8 | 899 | 10 格 | 底部完整，带数量 | `@uwnen` |
| 4 | `Mard(1471)` | 46×50 | 11 | 1471 | 10 格 | 底部完整，带数量 | `@椰豆` |
| 6 | 无标题，仅 `禁商禁转载·注明出处` | 45×80 | 7 | — | ~10 格 | **无图例** | 红色防盗文字 |

### 从样例里挖到的关键事实

**1. 图例数量之和 = 总豆数，三张样例 100% 成立（可自校验）**

- 图2：126+5+30+8+58+14+42 = **283** = 标题「共283颗」✓
- 图3：379+7+94+256+43+50+22+48 = **899** = 页面「共899豆子」✓
- 图4：159+96+8+13+84+27+61+329+59+226+409 = **1471** = 标题「Mard(1471)」✓
  → 说明 `Mard(1471)` 括号里不是图案ID，而是**总豆数**。

这条是本项目最重要的技术支点：**识别结果可以自我验证**。识别完只要算一遍各色数量，和图例/标题对不上就说明有格子错，可以自动定位可疑格。这把"要精准"从主观口号变成可量化的验收指标。

**2. 格子里写的字，不一定是色号**

- 图2/3/4/6：格子文字是标准色号（`H7`、`A20`、`E12`、`M15`…）
- 图1&5（颂拼豆）：同一片纯黄色的连续格子，文字依次是 `8 9 10 11 12 …18`，实测取样这些格子的填充色**完全一致**（约 RGB 255,220,95）。

  → 所以数字是**行内连续计数**（这一行这个颜色的第几颗），不是色号。
  → 结论：**颜色必须以"格子填充色"为准，文字只能当辅助校验**，否则图1这类会被彻底读错。

**3. 白色豆和空格子是同一个白色 → 必须靠"有没有文字"区分**

图3 眼白处是 `H2`（#FEFFFF 纯白豆），空白处也是白色。放大确认：白豆格子里印着 `H2` 文字，空格子没有任何文字。
→ 空格判定不能只看颜色，必须同时判断**格内是否存在文字像素**。

**4. 所有样例的色号都在 MARD 221 标准色卡内**

已核对：`A20 B26 C11 C12 E2 E4 E11 E12 F9 F13 F14 F16 F19 F21 G10 G14 G19 H1 H2 H7 M15 B4 B8 B13 B16 B18 B22 H5` 全部命中。
→ 内置 MARD 标准 221 色（9 个系列 A26/B32/C29/D26/E24/F25/G21/H23/M15）是正确选择；另需补全扩展系列，见第七节。
→ 实测填充色与 MARD 官方 HEX 的 RGB 距离普遍 < 10（E2 偏差 2~8，H7 偏差 0），**填色即官方色的直接映射是可行的**。

**5. 尺寸根本不只 50×50 和 100×100**

样例实际是 33×40、34×49、45×80、46×50、50×50。
→ "只支持 50×50 和 100×100" 不成立。建议改为：**任意 W×H，上限 100×100**（超过上限只做提示不阻断）。

**6. 粗线间隔不是固定的**

图1&5 粗线每 **5** 格一条；图2/3/4/6 约每 **10** 格。部分图还有虚线做 5 格细分。
→ 粗线间隔必须可配置（3~20 + 自定义），并支持"细线/虚线/交替色块"独立开关。

**7. 版面固定元素（识别时可直接利用）**

- 四边标尺：上/下 列号 1..W，左/右 行号 1..H
- 外框粗线一圈
- 标题元数据（3 种格式）：`[34x49/7色/共756颗]`、`(50x50尺寸·8色)`、`Mard(1471)`
- 底部图例条：色块 + 色号 + 数量（两种排版：色号在色块内 / 色块上方）

**8. 干扰项：水印/遮挡（这是必须正面处理的一类）**

实测归类为 5 种，处理方式完全不同：

| 类型 | 样例 | 特征 | 是否压到豆子格 |
|---|---|---|---|
| 半透明平铺水印 | `@uwnen`（图3）、`@椰豆`（图4） | 淡灰/淡彩、大号、周期性重复 | **会**（图4 压在绿色帽子上） |
| 红色防盗文字 | `禁商禁转载·注明出处`（图6） | 高饱和红、粗体、横跨多格 | **会**（横穿豆子区） |
| App UI 文字条 | `去汽水听》French Fuse（九块九块九）`（图2） | 不透明、黑底白字、覆盖整行 | **会**（盖住底部数行） |
| 侧边按钮/进度条 | ❤💬⭐🔗、`还原`、播放键 | 在网格框外 | 不会（网格框自动排除） |
| 图例被裁切 | 图1 底部只露 `G10 51 F23 35 H1 14` | 数量缺失 | 影响统计对账 |

- JPG 压缩把细网格线糊成近似白（实测空格区细线仅剩 1~2 级色差）
- 截图可能非整数像素对齐（实测格宽 ≈ 20.77 / 21.8 px）

## 二、识别引擎设计（要"够精准"，就是这五步 + 一票否决）

```
① 版面解析   → 标题取 (W,H,色数,总数)；定位图例条；定位网格外框
② 网格标定   → 由 W,H + 外框求单元格尺寸，再用检测到的格线位置做最小二乘亚像素精修
③ 逐格采样   → 取每格中心 60% 区域，剔除"文字色"像素后取众数色（抗 JPG 噪点、抗文字抗锯齿）
④ 空格判定   → 格内文字像素占比 < 阈值 且 填色≈背景色 → 空；否则为"豆"
⑤ 上色归属   → 有图例：以图例色块为调色板做最近色（CIEDE2000）；无图例：以标准 221 色最近邻
              → 特殊材质（P/Q/R/T/Y/ZG）不参与颜色匹配，只认格子文字/人工（见第七节）
              → 格子文字（若有）作为第三票仲裁
⑥ 自校验     → ①豆子总数 = 标题总数 ②每色数量 = 图例数量 ③文字色号 = 填色映射 ④"镜像/翻转"检测
```

**建议的"三重投票"**：填色、图例、文字，三者两票一致即判定；三者不一致的格子进"可疑清单"。
这样即使某一类图缺图例（图6）、或缺文字（部分App）、或文字是数字（图1），都还能出结果。

**"数量对不上"时的杀手功能（建议 P1）**：
若校验失败，自动找出**改动格子数最少**的修正方案（最小代价搜索），列出"把这 3 个格子从 E2 改成 E12 即可对上图例数量"，用户点一下确认即可。这比人工翻 2500 格可靠得多。

## 三、精度目标（可验收）

| 指标 | 目标 |
|---|---|
| 网格标定 | 格宽误差 < 0.3 px；100 格累积漂移 < 0.5 格 |
| 空格判定 | 白豆误判为空 / 空误判为白豆 = 0（靠文字判定兜住） |
| 单格色号 | 有图例时 100% 数量对齐；无图例时 ≥ 99%，且可疑格必须被标出 |
| 自校验 | 三张带图例样例必须做到"总数 + 每色数量"全部精确吻合 |
| 水印修复 | 水印压在豆子格上不得引起近色误判（E2↔E19 这类）；修复后数量对账仍须精确吻合 |
| 特殊材质 | R/T/Y/P 不允许由颜色静默推断；未确认的特殊簇必须出现在"待确认"列表；**T1 全透明绝不能被判成空格** |
| 选区 | 连通块选择 100×100 全图 1 秒内完成；删除/改色 10000 格即时刷新 |
| 可核验 | 界面提供「原图 / 识别结果」叠加对照，误差格标红，可单格改色 |

> 不承诺"永远 100%"，但承诺**错了一定会被发现**——这比谎报全对有用。

## 五、选区、编辑与删除（需求②增补）

### 5.1 选区能力（"连续选中"要做到三种粒度）

1. **同色全选**：点色号列表里的一项 → 全图所有该色格子（已有高亮复用同一套数据）
2. **连通块选择**（"连续"的核心）：点图上任意一格 → 选中**同色的 4 连通（或 8 连通）区域**。
   - 加 `Shift` 点第二格 → 追加选中另一块
   - 双击 → 递归选中"同色且相邻的所有块"
   - 提供 4 连通 / 8 连通 切换（斜向相连算不算连，拼豆上 8 连通更符合视觉直觉）
3. **框选 / 绘画选**：矩形框选、按住拖拽自由笔刷选中、橡皮减选
4. **按行/列/区间选**：选第 10~20 行该色的所有格子（拼豆按块施工时很实用）

**多选态**：色号列表支持 `Ctrl` 点选多项、`Shift` 连续区间选、全选、反选、按数量排序；列表里直接显示"已选 N 项 / 共 M 颗"。

### 5.2 选中之后的动作

| 动作 | 说明 | 备注 |
|---|---|---|
| **删除（置空）** | **默认语义已确认**：选中格子变空，不参与统计、不参与导出、不计入总数对账 | 破坏性 → 必须可撤销 |
| **改色** | 把选中格子统一替换成某个色号（**已确认要做**） | 图缺豆换色、水印格修正、特殊材质指定 |
| **仅从统计中排除** | 图上保留，但统计/清单里不算这个颜色 | 用于"这部分我没打算做" |
| **镜像/复制到对称位置** | 选中块复制到水平/垂直对称位 | 拼豆对称图案高频需求 |
| **局部重识别** | 对选中区域重新做一次取色（改完对齐参数后用） | 修错神器 |
| **外扩/内缩 1 格** | 选区扩一格/缩一格 | 补齐轮廓用 |

### 5.1b 选区的两种粒度（已确认）

点选一个格子时，按当前模式二选一：

| 模式 | 行为 | 用途 |
|---|---|---|
| **连通选区**（默认） | 只选中与它相连的**同一颜色连通块**（4/8 连通可选） | 删掉某个局部块、单独改一块的颜色 |
| **全部该颜色** | 选中**全图这个颜色的所有格子** | 整个颜色换色 / 整色删除 |

- `Shift` + 点击 = 追加选区（可叠加多个连通块）
- 两种模式随时切换，已选内容保留，可累加
- 选区确认后统一执行：删除（置空）/ 改色 / 排除统计 / 镜像…

### 5.3 删除的联动与安全

- 删除后：统计表、总数对账、导出预览 **实时刷新**
- 有图例时，"删除后总数对账"要区分两种账：`原始图例数量` vs `当前图案数量`，并显示差额（避免用户删完不知道自己少了几颗）
- **撤销 / 重做**（至少 50 步），删除前自动打快照
- 删除操作前若会破坏"数量对账"，给一次轻提示（不阻断）

## 六、水印与遮挡处理（需求②增补）

### 6.1 先明确一个关键优势

本工具是 **"识别成数据 → 再重绘"**，所以：

> **导出的图纸天然没有水印。**"用近似色覆盖水印"的真正难点不在输出，而在**识别阶段别被水印污染**。

因此本功能的本质是：**把水印像素从采样里踢掉，再用可靠信息推断出该格真实颜色**；推断出来的颜色既是数据，也是最终重绘时那一格的颜色——视觉上就是"水印被近似色覆盖掉了"。

水印只要压在**空格**上就无所谓（空格不显示填充）。真正必须处理的是压在**豆子格**上的水印（图4 @椰豆 压绿帽、图6 红字横穿、图2 UI 条盖底部数行）。

### 6.2 检测与修复（四级管线）

```
① 逐格双聚类：格内像素聚成 2 簇（填充色 / 覆盖物·文字），取大簇为主色，记录"污染占比"
② 水印掩膜（周期性）：残差图自相关求平铺周期 → 叠加得到水印模板 → 模板覆盖像素永久退出采样
③ 红字/UI 专用掩膜：高饱和红（R 高 G/B 低）判红字；检测不透明矩形/文字条判 UI 遮挡带
④ 覆盖率分级修复
     < 25%  → 众数取色，天然免疫（多数情况到此为止）
     25~70% → 只用未被模板覆盖的像素取样
     > 70%  → 标记 UNKNOWN，进入推断：a) 连通块内其余格多数票  b) "行内连续计数"数字冗余
                                              c) 排除图例中不可能出现的色
     推断仍失败 → 显示"?"格，进人工清单（绝不静默猜）
```

### 6.3 界面上要给的

- 识别完成后自动生成 **"污染格清单"**：受水印影响超过阈值的格子，红框标出并给出置信度
- **水印修复** 开关（默认开）：能自动修的静默修好；不能修的进清单
- **修复前后对比** 视图：原图 / 修复后并排
- 每格右键快捷：`用本格剩余像素重算` / `取邻格色` / `手动指定色号`
- **UI 遮挡带**（图2 的黑底白字条）处理方式不同：那是一整条不可识别区域，提示"该区域被应用界面遮挡，请换一张截图或手工补全"，并支持整行一键填空/继承邻行

### 6.4 验收标准

- 水印压在豆子格上时，**不得**因为水印而把 E2 判成 E19 这类近色错误（近色必须靠"排除污染像素"而不是整格中位数）
- 修复后的**数量对账必须仍然精确吻合**图例（这是水印修复是否成功的硬指标）
- 任何 UNKNOWN 格必须出现在清单里、可一键定位

## 七、色卡体系（MARD 全系列 295 色）

### 7.1 实际情况：MARD 不止 221 色

- **标准 221 色**：A26 / B32 / C29 / D26 / E24 / F25 / G21 / H23 / M15
- **扩展 74 色**：
  | 系列 | 名称 | 数量 | 识别策略 |
  |---|---|---|---|
  | P | 珠光 | 23 | ⚠ 文字/人工 |
  | Q | 温变 | 5 | ⚠ 文字/人工 |
  | R | 透明果冻 / 水晶（**半透明**） | 28 | ⚠ 文字/人工 |
  | T | 全透明 | 1 | ⚠ 文字/人工 |
  | Y | 夜光 | 9 | ⚠ 文字/人工 |
  | ZG | 光变 | 8 | ⚠ 文字/人工 |
- **合计 295 色**

### 7.2 三个数据源互不一致（已实测取舍）

| 来源 | 覆盖 | 结论 |
|---|---|---|
| [peiseka 配色卡](https://www.peiseka.com/pindouseka.html) | 221 | **实测与截图填充色最吻合 → 标准 221 采用此源** |
| [pixel-beads 2026 修订版](https://www.pixel-beads.com/zh-tw/mard-bead-color-chart) | 291（扩展 70：R28 但 Y 只有 5） | 作为兜底 |
| [pindouverse（GitHub）](https://github.com/cangelzz/pindouverse/blob/main/src/data/mard221.ts) | 295（扩展 74） | 扩展系列采用此源 |

**实测依据**：取图3 底部图例 8 个色块实测 RGB，与两套色卡比 ΔE：

| 色号 | 实测 RGB | peiseka ΔE | pixel-beads ΔE |
|---|---|---|---|
| E2 | (252,198,223) | 4.4 | 4.4 |
| E4 | (233,110,158) | 5.5 | 5.5 |
| E12 | (243,149,192) | 5.5 | 5.5 |
| F13 | (240,108,93) | **13.7** | 18.6 |
| F19 | (193,97,104) | 16.2 | 16.2 |
| F21 | (248,184,203) | **1.8** | 9.1 |
| H2 | (255,254,255) | 0.9 | 0.7 |
| H7 | (12,11,12) | 3.2 | 3.2 |
| **合计** | | **51.2** | **63.1** |

→ 结论：两个源都在"近似"范围内，**peiseka 偏差更小**，所以标准 221 用它；扩展系列用 295 版。
→ 295 色中有 **130 个色号三源 HEX 不一致**（多数在 ΔE 3 以内，但 A20、H1、T1、ZG1 这类差异较大）。
→ **所以别迷信色卡 HEX**，它只是屏幕近似值，真正可靠的是"以该图图例实测色为准"。

产物（已生成）：
- `pindou/mard-palette.json` —— 295 色合并版，每色带 `special`（是否特殊材质）、`matching`（`color`/`text`）、`consistent`（三源是否一致）、`sources`（三源 HEX 备查）
- `pindou/mard-palette.js` —— 前端可直接 `<script>` 引入的紧凑版（`window.MARD_PALETTE`）

### 7.3 最重要的一条设计结论：特殊材质**不能**靠颜色识别

74 个扩展色的共同问题：

- **温变 Q**：同一颗豆在不同温度显示完全不同的颜色，图纸上的填充色只是某一时刻的示意
- **光变 ZG**：实测在参考站上直接渲染成白色（#FFFFFF）
- **半透明 R / 全透明 T**：图纸上按"白底 + 网格透出"渲染，和白豆几乎无差别
- **夜光 Y / 珠光 P**：表面高光、偏色，RGB 不可靠

→ 所以这些色号必须标 `matching: "text"`：**只允许通过格子上的色号文字（OCR）或人工指定来判定，绝不参与 RGB 最近色匹配。**
否则典型事故：把半透明 `R11` 判成白豆 `H2`、把光变 `ZG1` 判成白色、把夜光 `Y9` 判成 `H1`。

→ 如果图纸里用了特殊材质、但格子上的字又读不出来：进"待定清单"，让用户点选，**不允许静默猜**。

### 7.4 近白 / 近黑簇同理

`H1`(半透明白) / `H2`(白) / `T1`(全透明) / `Y9` / `P1` / `H18` / `E16` 这些 RGB 几乎一样，同样只能靠文字区分；`H7`(黑) / `H16` / `H6` 也是同理（不过 Black 一般够黑，能靠颜色）。

### 7.5 工具里的三种匹配模式

1. **图例校准模式**（有图例，最准）：以图例色块实测 RGB 为本图调色板 → 逐格最近色
2. **标准色最近邻模式**（无图例）：只在 221 标准色里找最近（CIEDE2000）
3. **全系列模式**（含特殊材质）：标准色走颜色匹配，特殊系列走文字/人工
- 另加：**色卡版本切换**（221 / 291 / 295）与自定义色卡导入（P2），方便用户按自己手上的豆子选

### 7.6 用户实际使用的 4 个特殊系列：R / T / Y / P（共 61 色）

> 已确认：**半透明 R(28)、全透明 T(1)、夜光 Y(9)、珠光 P(23) 这四种用过**；温变 Q、光变 ZG 不用。
> → 所以这 61 色必须做扎实，Q/ZG 只留数据入口即可。

#### 7.6.1 核心方案：**簇级标注**（不做逐格 OCR）

整张图按"填充色"聚类，得到 N 个色簇（N 应当等于标题里的"N色"）。然后：

```
双聚类填色 → N 个色簇 → 标准色自动映射 ← 颜色最近邻
                        ↘ 特殊簇 → 一次性从对应系列里点选（R/T/Y/P 共 61 选 1，带色块预览）
         → 数量对账（每簇数量必须等于图例数量）→ 通过即结束
```

**为什么不做逐格 OCR**：100×100 是 10000 格，逐格 OCR 又慢又受字体影响；
而一张图的颜色最多 10~30 种，**人只需要确认 10~30 次**，且确认一次就整簇生效，准确率 100%。
逐格文字识别放 P1 做"自动化加速"，不是第一版的必需项。

#### 7.6.2 怎么判断"哪个簇是特殊材质"（三种信号）

1. **颜色超纲**：该簇填充色到 221 标准色的最小 ΔE > 阈值（如 12）→ 大概率不是标准色
2. **色数不匹配**：自动映射后，去重色数 < 标题"N色" → 说明有簇没被认出来
3. **文字前缀**：格子文字若可读且是 `R/T/Y/P` 开头 → 直接定性（P1 自动，P0 用户可见）

#### 7.6.3 半透明 / 透明在图纸上的版面特征（可自动预判）

- **半透明 R**：格子常渲染成"淡色 + 网格线透出/斜纹"，格内方差比实色格高
- **全透明 T**：常渲染成几乎无填充、只有边框或 X 标记
- **关键陷阱：T1 全透明 ≠ 空格**
  如果按"填色≈背景色即判空"，整片透明豆会被当成空白**删掉**，这是灾难性错误。
  → 空格判定必须再加一条：**格内有文字或边框/标记 = 豆；完全干净无标记 = 空**。
  → 透明豆在数据里是独立颜色（`T1`），导出的图纸上画成"格内打叉/斜线"而不是留白。
- **夜光 Y**：颜色偏亮、偏荧光，和标准色接近 → 若无文字，人工确认
- **珠光 P**：颜色偏"洗白"、明度高、饱和度低 → 同上

#### 7.6.4 渲染与统计上的材质差异（必须做，否则看图会错）

| 材质 | 格子渲染 | 说明 |
|---|---|---|
| 实色（221 标准） | 纯色填充 + 色号 | 现状 |
| 半透明 R | 半透明填充（网格透出）+ 色号 | 让人一眼看出"这是透明的" |
| 全透明 T1 | 无填充 + 斜线/叉 + 色号 | 绝不能画成空白 |
| 夜光 Y | 正常色 + 轻微光晕 | |
| 珠光 P | 正常色 + 高光小点 | |

统计表与导出清单要**多一列"材质"**（实色/珠光/半透明/全透明/夜光），因为采购是按材质分开买的。

## 八、数据模型（三块功能共用一个芯）

```js
Project {
  id, name, createdAt,
  source: { kind: 'pattern'|'photo', imageDataUrl, w, h },   // 原图
  meta:   { gridW, gridH, colorCount, totalBeads, palette: 'MARD-221' },
  align:  { x0, y0, cellW, cellH, rotation, corners? },       // 亚像素标定结果
  style:  { thickInterval, dashInterval, alternateBlock, showRuler, showCode },
  cells:  Uint16Array,        // 长度 gridW*gridH；0=空，1..n=调色板索引，65535=UNKNOWN(待人工)
  palette: [{ code, hex, rgb, count, series, material, special, excluded?, confirmed? }],
  // material: 'solid'|'pearl'|'translucent'|'clear'|'glow'（实色/珠光/半透明/全透明/夜光）
  // confirmed: 特殊材质是否已人工确认（未确认不得进最终统计）
  clusters: [{ id, sampleRgb, cells:[idx], autoCode?, code?, confidence, signals:['color-outspec'|'count-mismatch'|'text-prefix'] }],
  // 色簇标注面板的数据源：标准簇自动映射，特殊簇等人工点选
  paletteSet: 'MARD-221'|'MARD-291'|'MARD-295'|custom,        // 当前色卡版本
  legend:  [{ code, hex, count, box }],   // 图例解析结果（可能为 null）
  occl:    {                  // 水印/遮挡（需求②增补）
    templateMask: ImageBitmap|null,   // 周期性水印掩膜
    cellCoverage: Uint8Array,         // 每格被遮挡像素占比 0..100
    suspectCells: [ ... ],            // 污染格清单
    uiBands: [ {y0,y1,reason} ],      // App UI 遮挡带
  },
  selection: { type:'none'|'color'|'blob'|'rect'|'brush', set: Uint8Array|null, colors:[] },
  history: [ ... ],           // 撤销栈（快照式，≥50 步）
  checks:  { totalOk, countDiffs:[], suspects:[...] },
  highlights: [],             // 当前高亮色
}
```

**要点**：`cells` 一旦统一，需求①（图纸→数据）与需求③（图片→图纸）只是**填充 `cells` 的两种方式**，后面的高亮、统计、导出、编辑全部复用同一套代码。
